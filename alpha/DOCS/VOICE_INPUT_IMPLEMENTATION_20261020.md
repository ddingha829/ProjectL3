# 브라우저 음성 로그 입력 (2026-10-20)

## 사용 흐름

- 새 로그 작성/기존 로그 내용 수정에서 내용 아래 **음성 입력** 버튼을 누른다. 최초 마이크 허용은 브라우저가 처리한다. 페이지 진입만으로 마이크를 켜지 않는다.
- 한국어(`ko-KR`)를 인식하며 확정된 문구만 기존 내용 뒤에 이어 붙인다. 기존 문구와 직접 입력한 문구를 덮어쓰지 않는다. 반복되는 누적 결과의 동일 인덱스는 한 번만 추가한다.
- 인식 중인 문구는 별도 패널에 표시한다. 완료/오류 후에도 미확정 문구가 남으면 **내용에 추가 / 문구 지우기**로 선택한다. 미확정 문구는 자동으로 저장 데이터에 포함하지 않는다.
- **음성 입력 완료** 후 내용과 제목을 확인하고 기존 로그 저장 흐름으로 저장한다. 제목은 기존대로 직접 입력한다. 인식 중에는 저장 버튼/키보드 저장을 막고 마지막 결과 반영을 기다린다.
- 세션은 최대 2분이며 브라우저가 먼저 종료할 수도 있다. 자동 재시작하지 않는다. 필요하면 마이크를 다시 누른다. 한 번에 입력할 수 있는 내용은 기존과 동일하게 5,000자이다.

## 동작/비용 경계

- `SpeechRecognition` 또는 `webkitSpeechRecognition`을 사용한다. 새 패키지, 유료 STT API, Gemini 요청, 오디오 업로드/보관 엔드포인트는 없다. 앱에는 변환된 문구만 기존 로그/초안과 같은 방식으로 저장한다.
- 브라우저 음성 인식 서비스가 외부 서버로 오디오를 보낼 수 있다. 해당 안내를 버튼의 접근성 설명 및 인식 중 도움말에 표시한다. 모든 기기의 완전 오프라인 동작이나 무제한 서비스를 보장하지 않는다.
- 보안 연결/브라우저 API 지원/한국어 서비스/마이크 권한이 필요하다. 실패하거나 API가 없으면 키보드 마이크 대안을 안내한다. 카카오톡 인앱 등에서 생성자가 있어도 실제 서비스가 실패할 수 있어 오류와 시작 지연을 처리한다.

## 수명주기와 보호

- 완료는 `stop()`으로 마지막 결과를 기다린다. 종료 이벤트가 오지 않으면 3.5초 후 정리한다. 권한 대기 중 완료를 눌렀다가 늦은 시작 이벤트가 와도 다시 듣기 상태로 바뀌지 않는다. 시작 응답 대기는 최대 25초다.
- 탭 이동/언마운트/페이지 숨김/설정 오버레이/사진·세부 모달/사진 조정/입력 한도 도달 시 마이크를 종료한다. 오래된 결과 콜백이 초안에 뒤늦게 섞이지 않도록 세션 동일성을 검사하고 핸들러를 해제한다.
- 이미 확정된 내용은 초안 복구 대상이다. 화면을 떠나며 중단한 미확정 음성까지 복구한다고 약속하지 않는다. 오류 시 반영된 내용은 유지한다.
- 마이크·전송 상태는 텍스트와 아이콘으로 표시한다. 버튼은 44px 이상이며, 인식 패널의 제스처가 상위 탭 전환과 충돌하지 않게 한다. 기존 첫 사용자 가이드도 음성 입력/확인 흐름에 맞췄다.

## 검증

- `npm run typecheck`, `npm run build`.
- `test:voice`: 실제 Chrome/Playwright WebKit 브라우저에서 인식 이벤트를 모의 주입해 한국어 설정, 중간/최종/반복 결과, 직접 타이핑 보존, 완료 후 마지막 결과, 미확정 문구 선택, 재시작, 권한/네트워크/기기 오류, 설정·사진·백그라운드·탭 이동 정리, 늦은 콜백 차단, 5,000자 제한, 새 로그 저장/기존 내용 수정, 접두사 API/미지원/동기 예외/종료 지연, 320~1280px 및 양쪽 테마를 검증한다.
- `test:oct20-browser`: 기존 카드 제스처·대기 3D·좌우 배치·사진 톤·책/TMDB·가이드 회귀 확인.
- 자동화는 UI/결과 처리 검증이며 실제 음성 정확도나 실제 iPhone/Android/PWA/카카오 인앱의 인식 서비스 성공을 뜻하지 않는다. 테스트에서 실제 마이크 권한을 요청하거나 사용자의 음성을 녹음하지 않았고, 운영 로그/계정은 변경하지 않았다.
