### 추가 요청: 초기 문구 폰트

‘무슨 일상을 로그할까요?’의 CSS에 남아 있던 Pretendard 지정도 제거했다. 캔버스 측정도 현재 선택한 실제 폰트를 사용하도록 변경하고, 글꼴 변경·로딩 완료 시 너비를 다시 계산한다. 잔물결과 한 줄 크기 조절은 유지한다.

## 점검 중 추가로 보강한 부분

- 텍스트 입력·선택, 버튼·프리셋 조작을 페이지 넘김으로 오인하지 않도록 전역 스와이프 시작 대상을 제한했다. 로그북 포스터 카드에서는 페이지 스와이프를 유지한다.
- 빈 구형 로컬 캐시가 보안 재연결 표시만으로 로그인을 막지 않게 했다. 기록이 남은 구형 캐시는 보관된 복원 코드로 소유권을 확인하고 연결을 복원한 후 동기화한다. 잘못된 복원 정보로 기록을 임의 계정에 업로드하지 않는다.
- 캐시에 남은 과거 재연결 표시만 보고, 정상 Google 로그인 직후 잘못된 보안 업데이트 알림을 띄우지 않도록 수정했다.
- 운영 Storage 업로드 오류를 임시 파일 저장 성공으로 처리하지 않게 했다. 오류는 기기 outbox에 남고 재시도할 수 있다.
- 새 로컬 글꼴을 PWA 오프라인 캐시에 포함했다. 단어 하나에 불필요한 전체 필기체 대신 공식 Google Fonts의 해당 문구 서브셋 약 6.9KB만 사용한다.
- 카드 내보내기는 Sebang이 사용되는 곳에서 불필요한 Pretendard/Inter 대체 폰트를 함께 임베딩하지 않는다.

## 운영 확인과 Google 설정

- `l2_profiles`, `l2_archives`, `l2_ai_usage`: 서버 키로 조회 성공, 공개 anon 키의 데이터 접근은 차단됨.
- Storage 버킷 조회 성공. 최근 저장 사진 세 개가 HTTP 200으로 응답했으며 약 105~201KB였다. 기존 JPEG와 WebP가 함께 있으며, 과거 파일을 일괄 재변환하지 않았다.
- 신규 사진 업로드는 클라이언트 WebP, 최대 너비 1080px, 품질 0.8, 300KiB 이하를 검증했다. 브라우저 네이티브 WebP 미지원 시 로컬 WASM 대체 경로도 통과했다.
- 카드 20종 × 비율 3개가 JPEG, 최대 너비 1080px, 500KiB 이하로 실제 내보내졌다. 실제 TMDB CDN 이미지가 먼저 일반 이미지 캐시에 들어간 상황의 내보내기·공유도 통과했다.
- 사용자의 확인을 받은 뒤, 기존 Supabase 인증 허용 주소는 유지하고 아래 두 주소를 추가 저장했다.
  - `https://project-l3-nine.vercel.app/api/auth/google/callback`
  - `http://localhost:3013/api/auth/google/callback`
- 기존 공유 프로젝트의 Site URL `https://ticgle.kr`는 변경하지 않았다.
- 실제 로그인은 로컬 앱에서 기존 Google 인증 세션을 통해 완료되었고, 설정의 Google 계정명과 서버 동기화 완료 상태를 확인했다. 운영 사이트에 새 버튼이 노출되는 것은 이번 코드 배포 이후다.
- 참고한 공식 OAuth/PKCE 문서: https://supabase.com/docs/guides/auth/social-login/auth-google

## 로그인 진입 제안

원했던 ‘설치 → 로그인 안내’ 순서는 유지하는 편이 좋다. 첫 화면에서 Google 연결을 가장 쉬운 선택으로 제공하되 ‘나중에’를 남기는 방식을 권장한다. 로그인 강제 여부는 변경하지 않았다. 비회원 체험 후 연결해도 기록이 이어지므로, 설치·가입 부담과 데이터 보관을 함께 다룰 수 있다.

## 향후 별도 Supabase 이전 시

사용자 확인: 현재는 예전 프로젝트를 임시로 공유하며, 테스트 후 새 Supabase 프로젝트로 옮길 예정이다. 지금 이전 작업을 실행한 것은 아니다.

1. 새 프로젝트에 L3 테이블·인덱스·사용량 RPC·RLS를 설치하고 anon 차단, service-role 서버 접근을 확인한다.
2. Google provider와 Google Cloud의 새 Supabase callback URI를 구성한다. ProjectL3의 운영/개발 redirect URL도 새 프로젝트에 등록한다.
3. Google Auth UUID를 보존하는 지원된 이전 방식 또는 명시적인 구/신 사용자 UUID 매핑을 준비한다. Auth를 새로 만들면서 DB의 owner_id만 그대로 복사하면 같은 Google 계정도 기록이 안 보일 수 있다. `l2_profiles.id`, `l2_archives.owner_id`, `l2_ai_usage.owner_id`를 함께 검증한다. ID/비밀번호 계정도 별도 유지 대상이다.
4. 사진 버킷과 객체를 옮기고 기록/저장 카드 스냅샷/그룹의 이전 Storage URL을 새 URL로 변경하거나 호환 경로를 확보한다. TMDB 외부 URL은 서버 사진으로 복사할 필요가 없다.
5. Vercel Production·Preview 및 로컬 env의 Supabase URL/anon/server 키를 교체한다. 세션 서명 키 변경 시 기존 기기 재로그인·복원 동작을 점검한다. 이 문서에 비밀 값을 기록하지 않는다.
6. 계정별 로그·그룹·프리셋·사진 수, 로그인/로그아웃/재로그인·오프라인 outbox·기기 간 조회를 비교한 뒤 기존 임시 프로젝트 연결을 해제한다.
