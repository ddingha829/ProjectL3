# 2026-10-21 UI/UX 제안 1–5 적용

## 1. 눈으로 고르는 디자인·팔레트

- 카드 상세와 스튜디오의 디자인 선택에 현재 사진·제목·본문·색상을 넣은 실제 카드 썸네일을 표시한다. 지원하지 않는 비율은 기존 유효 비율 규칙을 따른다. 그룹용 LIST와 일반 로그의 호환 규칙을 유지한다.
- 썸네일은 보이는 영역 가까이에서만 렌더링하며 고정 공간을 예약한다. 정적인 미리보기이므로 3D 효과나 내보내기 캡처 참조를 만들지 않는다.
- 팔레트는 세 색 점 대신 배경·제목·보조 글자·강조색으로 구성한 예시를 보여준다. 3열과 삭제/생성 기능은 유지한다. 스크롤 중 선택창의 제목과 닫기 버튼이 남는다.

## 2. 카드를 보면서 세부사항 조절

- 공용 CardDetailsDialog를 추가했다. 모바일은 위 카드/아래 설정, 760px 이상은 왼쪽 카드/오른쪽 설정이다. 카드와 완료 버튼을 고정하고 설정 영역만 필요할 때 스크롤한다.
- 비율은 항상 보이며 표시 항목과 사진 보정은 하나씩 펼친다. 실제 로그·회원·서명을 그대로 미리 보며 변경은 기존 호출자의 초안으로만 반영한다.
- 티켓의 1:1 비활성화, 디자인별 표시 항목, 채도·명도·밝기와 초기화 동작을 유지한다. 일반 선택·설정 변경은 여전히 명시적 카드/프리셋 저장이 필요하다.

## 3. 되돌리기·다시 실행·원본 비교

- 카드 상세와 스튜디오 모두 세션 내 최대 40단계 기록을 제공한다. 프리셋/양식/팔레트/표시/비율/사진 보정/사진 크롭, 스튜디오 이름과 예시 종류 변경을 포함한다.
- 600ms 이내에 이어지는 같은 슬라이더 또는 이름 변경은 하나로 묶는다. 시작값으로 돌아온 제스처는 빈 단계로 남기지 않는다. Undo 뒤 새 변경은 이전 Redo 분기를 지운다. 카드 전환이나 저장으로 기준이 바뀌면 기록을 새로 시작한다.
- 원본 비교는 저장 전 모양을 별도 미리보기로 덮어서 보여준다. 실제 캡처 노드·미저장 초안·저장 데이터는 바꾸지 않는다. 비교 중 공유해도 현재 편집본을 내보낸다. 세부사항 창 안에서도 같은 기록과 비교 버튼을 쓸 수 있다.
- 삭제/팔레트 삭제/계정 변경/새 프리셋 생성은 디자인 Undo의 범위가 아니다. 사진 파일이나 서버 데이터를 복사하는 범용 변경 이력이 아니다.

## 4. 모바일 키보드 대응

- 사진/장소/세부설정과 저장을 입력 박스 밖 공용 footer로 분리했다. 기존 visualViewport 기반 높이와 포커스 처리에 맞춰 휴대폰 입력 중 44px 아이콘 세 개와 저장 버튼을 한 줄에 둔다.
- 숨긴 글자는 aria-label과 title로 유지한다. 키보드를 닫으면 원래 텍스트 버튼 배치로 돌아간다. 본문 내부 스크롤과 기존 초안·음성·사진 기능은 유지한다.
- 내용 수정 시트에도 같은 조합을 적용한다. 입력 중 불필요한 하단 삭제 동작은 숨기고 키보드를 닫으면 다시 표시한다. 사진과 입력 영역이 저장 행을 밀어내지 않도록 크기를 제한한다.

## 5. 짧은 첫 가이드와 전체 다시 보기

- 각 화면의 최초 안내는 핵심 3단계다. 로그 작성은 제목/내용/저장, 꾸미기·지도·그룹은 해당 화면의 첫 진입에서 소개한다. 각 단계는 대상 강조 오버레이를 유지하고 마지막 단계에서 종료한다.
- 설정의 ‘사용 가이드 다시 보기’를 누르면 전체 가이드 모드로 전환한다. 기존 상세 설명은 삭제하지 않았다. 모드는 기존 localStorage 가이드 상태에 선택적으로 저장하며, 기존 설치 사용자에게 안내를 다시 강제로 띄우지 않는다.

## 검증

- `npm run build`, `npm run typecheck`, `test:design-history`, `test:repository`.
- `test:ux-polish`를 Chrome/Playwright WebKit에서 실행: 같은 내용의 썸네일/실제 디자인 선택, Undo/Redo/슬라이더 묶음, 카드가 보이는 세부사항(320×568, 390×844, 768×1024, 1280×900), 원본 비교 중 편집본 PNG 공유, 저장 기준 초기화, 스튜디오 이력, 3단계 최초 안내/전체 다시 보기.
- 키보드는 visualViewport 높이를 460px로 바꾸어 44px 버튼과 저장 영역이 보이고 원상 복귀하는지 검사한다. 실제 Android/iPhone의 네이티브 키보드를 직접 조작한 검사는 아니다.
- 기존 카드 3D·제스처·사진 보정·책/TMDB·프리셋 저장·공유 회귀 검사를 유지한다. 가이드/공유 선택 단계 변경에 맞춰 관련 브라우저 테스트를 갱신했다.
- 모든 데이터 쓰기는 API fixture/격리 저장소에서만 실행한다. 유료 공급자 호출이나 운영 사용자 데이터 쓰기는 하지 않는다.

UI/UX Pro Max의 focus-not-obscured 지침을 참고했다. 새 페이지용 디자인 시스템이나 외부 UI 패키지는 추가하지 않았다.
