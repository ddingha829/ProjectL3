# 저장 완료 피드백 적용 및 추가 UX 제안

2026-10-17 · 로컬 Alpha 적용 · 기존 Vercel/Supabase 연결 유지

## 적용한 흐름

1. `로그 저장`을 누르면 기존처럼 분류 선택창을 엽니다. 이때는 저장 성공 표시나 진동을 내보내지 않습니다.
2. 분류를 선택하면 중복 제출을 잠그고 IndexedDB의 영속 저장 완료를 기다립니다. 서버 동기화 응답 때문에 작성 흐름이 멈추지 않습니다.
3. 저장된 뒤에만 같은 체크 표시와 지원 기기의 짧은 22ms 진동 한 번을 사용합니다. 선택한 분류에 `저장됨`을 약 220ms 표시합니다.
4. 완료 표시 중에는 방금 입력한 내용이 그대로 보이지만 복원용 초안은 이미 비워집니다. 완료 후 로그북으로 이동합니다.
5. 새 로그가 목록에 한 번 안착하고 약한 강조가 사라집니다. 기존 로그는 다시 움직이지 않습니다. 새 로그가 키보드 포커스를 받아 바로 열 수 있습니다.
6. 새 로그의 등장은 화면 슬라이드와 160ms 간격을 두어 겹침을 줄입니다. 카드 상세를 열었다 돌아오거나 재접속해도 다시 등장 효과를 내지 않습니다.

설치·가입 안내의 시점은 유지했습니다. 카드 상세의 기본 동작 이름은 `카드 저장` / `공유하기`입니다. 카드 저장도 완료 후 같은 체크 표시와 `저장됨`을 보여주고, 변경이 없는 상태에서 불필요하게 다시 저장하지 않습니다. 저장 결과 안내는 `로그북에 저장했어요`로 통일했습니다.

## 실패·접근성·오프라인

- 저장 완료의 기준은 기기의 영속 저장입니다. 오프라인에서는 `기기에 저장했어요`로 안내하며 서버 동기화 성공을 주장하지 않습니다.
- 기기 저장이 실패하면 체크·완료 진동·화면 전환 없이 제목과 본문을 유지합니다. 분류 선택창에서 바로 다시 시도할 수 있습니다.
- 완료 순간의 짧은 구간에 연속 제출과 탭 전환을 막아 중복 기록이나 이동 충돌을 줄였습니다.
- 모션을 끄면 이동 애니메이션을 생략하고 체크와 문구로 결과를 전달합니다. 진동은 사용자 설정과 기기 지원 여부를 따릅니다.
- 동기화로 편집 대상 객체가 바뀌더라도 현재 편집 세션을 초기화하지 않도록 수정했습니다.

## 검증

`npm run typecheck`, `npm run build`, `npm run test:repository`, `npm run test:save-feedback`.

새 UI 테스트는 API 요청을 격리된 가상 응답으로 처리하고 실제 IndexedDB를 사용합니다. 운영 Supabase 데이터에는 테스트 기록을 쓰지 않습니다. 검증 항목은 다음과 같습니다.

- 영속 저장 → 체크·진동 → 목록 진입 순서.
- 연속 클릭 중복 방지, 지연된 서버 응답과 독립적인 완료.
- 기존 로그의 정지, 상세 복귀 시 등장 효과 재생 방지.
- 카드 저장·내용 수정의 완료 상태와 원래 카드로 복귀.
- 기기 저장 실패 시 입력 보존 및 재시도.
- 오프라인 저장, 모션 끄기, 재접속 후 제출한 초안·중복·등장 효과가 남지 않음.
- 320×568 / 768×1024 / 1280×800에서 분류 선택창 접근.

Chrome 자동화로 검증했으며 실제 iOS 키보드·시스템 공유와 햅틱 촉감까지 검증한 것은 아닙니다.

## 직접 보면서 찾은 다음 개선 후보

아래는 추가 제안이며 이번 패치에 포함하지 않았습니다.

1. **설치 안내와 메뉴의 겹침 해소.** 설치·가입을 먼저 권하는 정책은 그대로 유지하되, 좁은 화면에서 설치 팝업이 상단 탭을 덮지 않게 배치할 필요가 있습니다. 자동화 검증에서도 팝업을 닫기 전에는 탭 클릭이 가로막혔습니다.
2. **지도 미연결 안내의 대상 좁히기.** 장소를 적지 않은 기타 일상 메모에도 제목만으로 위치 연결 안내가 생깁니다. 실제 장소 의도가 있는 로그에만 제안하면 개인 메모 목록이 더 깔끔해집니다. 주소·장소 선택 여부와 카테고리를 함께 판단하는 방향을 권합니다.
3. **카드 상세에서 돌아올 때 탐색 맥락 복원.** 로그북이 다시 마운트되면 검색·분류·보기·스크롤이 초기화됩니다. 새 로그 저장 시에는 최신 목록으로 이동하되, 단순 상세 열람 후에는 보던 위치를 복원하는 편이 자연스럽습니다.
4. **미확정 카드 디자인 보관.** 프리셋을 시험하다 나가면 임시 디자인이 사라집니다. 현재 수동 저장 정책은 유지하면서 기록별 임시 상태를 복원하거나 이탈 시 취소 사실을 짧게 알리는 방안을 검토할 수 있습니다.
5. **모션 설정의 다시 켜기 의미 정리.** 현재 토글의 켜기는 `auto`여서 OS의 동작 줄이기가 활성화된 환경에서는 표시상 켜져도 움직이지 않을 수 있습니다. 명시적 켜기와 기기 설정을 구분하는 방향을 검토하면 앞서 발생했던 혼동을 줄일 수 있습니다.

우선 추천은 **설치 팝업의 메뉴 겹침 → 로그북 탐색 맥락 복원 → 지도 안내 정리**입니다. 모두 첫 작성과 기록을 다시 찾아보는 흐름에 직접 영향을 줍니다. 인증·접근 권한 및 데이터 이관 문제는 기존 `HANDOVER_REVIEW.md`의 별도 우선 과제로 유지합니다.
