# 프리셋 보관함 · 로그별 디자인 후속 작업 (2026-10-18)

사용자가 승인한 `mockups/preset-library-v2.html`의 관리 방식을 실제 앱에 적용했다. 아래 내용이 과거 문서의 ‘목업만 제안’, ‘카드 상세는 프리셋만 선택’ 설명보다 우선한다.

## 요청별 대응

| 요청 | 적용 |
|---|---|
| 프리셋 드래그가 글자 선택으로 오인되고 추가/순서 변경이 모호함 | 현재 프리셋을 누르면 실제 카드 썸네일 보관함이 열린다. 스튜디오의 ‘정리’에서 항목 선택 → 삽입 위치 선택 → ‘순서 저장’으로 확정한다. 취소하면 기존 순서가 유지된다. 마우스·터치·키보드 모두 같은 버튼 흐름이며, 이전 앞으로/뒤로 팝업과 드래그 핸들은 제거했다. |
| 프리셋 추가 흐름 | 보관함의 ‘새 프리셋’에서 이름, 사진용/텍스트용/그룹용, 현재 디자인 복제/새 디자인을 명시적으로 고른다. ‘만들고 편집하기’가 이름 있는 프리셋을 먼저 보관한 뒤 스튜디오로 돌아온다. 이후 디자인 변경은 ‘프리셋 저장’으로 저장한다. 최대 20개. |
| 스튜디오 역할 | 반복 사용할 원본 프리셋 제작·관리, 전체/카테고리 기본값 지정. 이미 저장된 로그의 디자인 스냅샷은 덮어쓰지 않는다. |
| 카드 상세에서도 디자인/색상/세부사항 조정 | 프리셋 보관함 + 이전/다음 선택을 유지하면서 개별 디자인 도구를 추가했다. 디자인·팔레트·비율·표시 항목을 고른 뒤 ‘카드 저장’하면 현재 로그에만 반영된다. 원본 프리셋과 다른 로그는 그대로다. |
| 저장/취소의 의미 | 미저장 표시와 ‘변경 취소’를 제공한다. 내용 수정은 같은 카드의 시트에서 이루어지고, 임시 디자인을 지우지 않는다. ‘카드 저장’은 로그에 디자인을 보관하고, ‘공유하기’는 현재 카드 이미지 및 연결된 실제 Google 지도 주소를 전달한다. |
| 그룹/사진 호환 | 그룹은 보관함과 세부 디자인 모두 LIST만 허용한다. 일반 로그에는 LIST를 보여주지 않는다. 사진 없는 로그는 텍스트용 레이아웃만 편집한다. |
| 세방고딕 이탤릭 활용 | 제공된 Regular/Bold 이탤릭을 같은 로컬 글꼴 가족에 추가했다. 에디토리얼 브랜드, 잡지 머리글, 풀블리드 짧은 인용문에 선택적으로 사용한다. 전역 이탤릭 옵션은 만들지 않았다. 제목·입력·긴 본문은 정자체다. 기존 글꼴 복원 옵션은 유지한다. |
| 초기사용자 가이드 | 로그/로그북/카드/스튜디오/설정 안내를 현재 흐름에 맞췄다. 카드 안내는 ‘이 로그만 꾸미기’, 스튜디오는 ‘다시 쓸 프리셋 만들기’를 설명한다. 새 보관함·순서 정리·이름 지정·카테고리 기본값·저장의 역할을 명시한다. 대상 강조 오버레이, 탭으로 다음 단계, 마지막 단계 종료, 기존 사용자 자동 재노출 방지와 설정의 다시 보기 규칙을 유지한다. |

## 점검 중 보강

- 팔레트 선택 컴포넌트 사이에 삭제 tombstone을 전달하여, 삭제한 기본 색상이 다시 등장하지 않도록 수정했다. 마지막 팔레트 보호와 저장된 카드 색상 보존을 확인했다.
- 순서 삽입 버튼 높이를 일정하게 유지하고, 이동 뒤 해당 항목으로 키보드 초점을 돌린다.
- 저장 중 프리셋 전환·이름/종류 변경을 막는다. 새 프리셋 생성에는 중복 제출 잠금이 있다.
- 내보내기 폰트 임베딩은 정자체/이탤릭과 실제 사용 굵기를 구분한다. PWA 캐시 v7에 모든 로컬 글꼴을 포함했다.
- 단일 카드의 저장 전 스타일 비교는 JSON 속성 순서나 프리셋 이름이 아닌 실제 디자인 속성으로 판단한다.

## 검증

격리된 로컬 서버 `127.0.0.1:3014`와 API fixture를 사용했다. 운영 개인 기록의 삭제/초기화나 유료 생성 호출은 하지 않았다.

- `npm run build`: 성공.
- `test:ui` / `test:preset-workflows`: 썸네일 선택, 정리 취소/저장/재접속, 키보드 이동, 이름 있는 프리셋 생성, 카테고리 기본값, TMDB 실제 CDN 내보내기, 로그별 디자인 저장·취소·내용 수정, 원본 프리셋/다른 로그 불변성 통과.
- `test:frontend-round2`: 320×568 / 390×844 / 768×1024 / 1280×900 헤더·스튜디오·필기체 위치·폰트 복원·입력 제스처·경계 반발·필터 통과.
- `test:guides-studio`: 첫 방문 가이드/단계 진행/재노출 방지/재생, 카드 보관함의 관리 버튼 비노출, 공유 데이터, 색상 삭제·마지막 색상 보호, 320~1280px 레이아웃 통과.
- `test:save-feedback`: 중복 저장 방지, 로컬 저장 성공/실패 반응, 내용 수정, 오프라인 저장 통과.
- `test:ux-upgrade`: 설치 안내, WebP 압축·WASM 대체, TMDB, 삭제 제스처, 반응형 카드 그리드, 그룹 호환, ZIP·확인 후 초기화 통과.
- `test:repository`, `test:stability`, `test:google-auth`: 저장/동기화/계정 분리, 서명 세션, PKCE/서버 identity 검증/게스트 이전과 실패 경로 통과.
- `test:card-exports`: 20개 레이아웃 × 3개 비율이 JPEG, 너비 1080px 이하, 500KiB 이하로 내보내짐.
- `test:pwa`: 비공개 API 캐시 금지, 모든 로컬 폰트 사전 캐시, 오프라인 새로고침/작성/재연결 및 중복 방지 통과.

`test:ui`는 최신 사용자 흐름을 검사하는 `test_preset_workflows.mjs`로 연결했다. 과거 `test_workflow.mjs`에는 이전 PNG 크기·옛 UI 가정이 남아 있으며 이번 검증 대상으로 보고하지 않는다. Windows Chrome/Edge와 터치 에뮬레이션 기준이며 실제 iPhone/Safari의 OS 공유창은 별도 기기 확인 대상이다.

기존 Google 로그인/백엔드 점검과 Supabase 이전 계획은 `FRONTEND_AUTH_REVIEW_20261018.md` 참조. Git push·배포 결과는 저장소 커밋 및 Vercel 상태로 확인한다.
