# 사진 맞춤 · 확대 · 드래그 (2026-10-18)

## 사용 방법

카드 상세 → **사진 조정** → **전체 보기 / 여백 채우기** 또는 **확대(100~300%)** → 사진을 직접 드래그 → **적용** → **카드 저장**.

- 전체 보기는 사진 전체를 보존하므로 비율에 따라 여백이 생길 수 있다. 여백 채우기는 사진 영역을 가득 채우며 일부가 잘린다.
- 사진 조정 창은 실제 카드의 현재 비율·디자인으로 미리 보여준다. 취소/닫기는 이 창의 변경을 버린다. 적용은 해당 카드의 임시 변경이며, 카드 저장으로 확정한다. ‘변경 취소’는 저장 전 카드/사진 상태를 함께 복원한다.
- 내용 수정/로그 작성의 사진 위치 조정에서도 직접 드래그를 제공한다. 가로·세로 슬라이더는 대체 조작으로 남기고 확대/맞춤 선택을 추가했다. 사진 이동 중에는 메모 포커스나 상위 페이지 스와이프가 실행되지 않는다.
- 방향키로도 이미지를 이동할 수 있다(Shift로 큰 이동). 터치 드래그는 사진 조정이 켜진 사진 영역에서만 잡으며, 주변 페이지의 스크롤·브라우저 확대는 전역으로 차단하지 않는다. 두 손가락 핀치 확대는 이번 범위에 포함하지 않았다.
- 사진이 없는 디자인과 그룹 카드에서는 카드 상세의 사진 조정 버튼을 숨긴다. 스튜디오 원본 프리셋에는 사진 구도를 저장하지 않는다.

## 저장 및 호환

- `ArchiveItem.cropZoom`(1~3), `photoFit`(contain/cover)을 기존 `cropX/cropY`와 함께 보관한다. 값은 서버에서 유효 범위로 정규화한다. 옛 로그/초안은 확대 1배, 기존 레이아웃 기본 fit으로 호환된다.
- 기존 Supabase `l2_archives.data` JSON, 파일 저장소, IndexedDB/outbox 경로를 그대로 사용한다. SQL 컬럼이나 Storage 사진 복제는 추가하지 않는다. 원본 사진 URL/크기는 바꾸지 않는다.
- 새 사진/TMDB 포스터로 교체할 때 기존 확대와 맞춤을 초기화한다. 내용만 수정할 때는 사진 구도를 보존한다.
- 사진 표시와 드래그의 공통 구현은 `PhotoViewport.tsx` 및 `photoCrop.ts`이다. 이미지 영역의 실제 표시 크기를 사용해 축소된 카드에서도 손가락 이동량과 이미지 이동량을 맞춘다.
- 이미지 내보내기는 이 구도가 반영된 스냅샷을 사용한다. 확대된 이미지가 카드 영역 밖으로 나오지 않도록 기존 photo overflow clipping을 유지한다.

## 검증

- 프로덕션 빌드 및 TypeScript 성공.
- `test:photo-adjust`: 마우스 양축 드래그, 실제 CDP 터치 포인터 이벤트, 방향키, 전체/채우기, 확대, 창 취소, 카드 변경 취소, 카드 저장/새로고침, 원본 프리셋·다른 로그 불변성 통과. 내용 수정 화면 터치 드래그가 메모 포커스·페이지 전환으로 새지 않는 것을 확인했다.
- 같은 테스트에서 공유 JPEG의 사진 픽셀을 확대/이동한 원본의 예상 좌표와 비교해 구도 일치를 확인했다. 320×568, 390×844, 768×1024, 1280×900 조정 창 버튼 가시성을 검사했다.
- 격리 서버의 `storeKind=file`을 확인한 뒤 실제 API 생성 → 내용만 수정 → 재조회에서 구도가 보존되는 것을 확인하고 해당 QA 로그만 삭제했다. 운영/Supabase 개인 기록은 변경하지 않았다.
- `test_ticket_webkit.mjs`: 실제 Playwright WebKit에서 확대·드래그·공유 픽셀 비교 통과. Windows WebKit 기준이며 실제 iPhone의 OS 공유창은 별도 범위다.
- `test:repository`, `test:preset-workflows`, `test:ux-upgrade`, `test:ticket-export`, `test:card-exports`(20종/59비율 조합), `test:pwa` 회귀 통과. PWA 오프라인 작성/재연결, 이미지 압축, 사진 누락 실패/재시도도 유지했다.
