# 2026-10-21 로그북 복귀 · 실제 날짜 · 백업 복원 · 공유 공개 범위

승인된 제안 1·2·3·5를 반영했다.

## 사용자 흐름

1. **로그북 복귀 상태 유지**: 검색어·분류·보기·정렬 상태를 상위 화면에서 보관한다. 카드에서 로그북으로 돌아오면 이전 스크롤과 선택 로그의 포커스를 복원한다. 새 로그 저장 후에는 새 로그를 볼 수 있도록 기본 목록으로 이동한다. 상태는 현재 앱 세션 안에서 유지되며 새로고침 후 복원이나 지도 확대/중심점 보관은 포함하지 않는다.
2. **실제 일어난 날짜·시간**: 로그 작성/내용 수정 → 세부 설정에 한국 시간 입력을 추가했다. 선택값은 `occurredAt`에 저장하며 최초 저장 시각 `timestamp`와 기존 `date`는 변경하지 않는다. 카드 날짜·로그북 정렬·캘린더 날짜/시각·지도 경로 순서는 실제 시각을 우선 사용한다. 비워두거나 ‘저장한 시간으로’를 누르면 기존 저장 시각을 사용한다. 기존 로그는 일괄 변경하지 않는다.
3. **백업 복원**: 설정 → 데이터 백업 영역 → 백업 파일 복원에서 ZIP/JSON을 선택한다. 추가 예정·중복·잘못된 형식·사진 누락과 일부 제목을 먼저 보여준다. 확인 전에는 쓰지 않는다. 기존 로그는 덮어쓰지 않고 새 로그만 IndexedDB 한 트랜잭션으로 추가한 뒤 기존 outbox로 서버에 동기화한다. 완료 문구는 기기 복원과 서버 동기화를 구분한다.
5. **이번 공유의 공개 범위**: 카드 상세 → 공유하기에서 지도 링크·구조화된 위치 문구·서명을 각각 선택한다. 이미지 미리보기를 반영하고 필요한 PNG를 다시 준비한 후 네이티브 공유/다운로드를 시작한다. 원본 로그와 프리셋에는 저장하지 않는다. 본문이나 사진 자체에 사용자가 적은 주소/이름을 자동으로 가리는 기능은 아니다.

## 데이터 호환 및 복원 정책

- 새 필드 `ArchiveItem.occurredAt?: number | null`은 기존 JSON 데이터에 추가한다. Supabase `l2_archives.data` JSONB를 사용하므로 SQL 마이그레이션은 필요 없다. 서버 API 정규화, 로컬 초안, 재시도 큐, JSON/ZIP/CSV 백업을 통과한다.
- ZIP은 기존 내보내기의 `logs.json`, `manifest.json.images`, `images/*` 구조를 읽는다. JSON은 로그 배열 또는 `{archives: [...]}`를 지원한다. CSV 단독 가져오기는 지원하지 않는다.
- 기존 ID는 건너뛴다. 새 ID는 목적지 계정 범위와 원본 ID에서 결정적으로 만든다. 같은 계정의 같은 백업 재복원은 중복 추가되지 않으며 다른 계정의 전역 PK와 충돌하지 않는다. 동일 내용의 별도 ID를 추측해서 병합하지 않는다.
- 복원 outbox는 `appendOnly`로 전송한다. 서버/API/저장소도 기존 항목을 업데이트하지 않으며, Supabase의 동시 insert 충돌은 소유권을 확인한 기존 행을 읽어 해결한다. 다른 기기의 최신 수정본을 오래된 백업으로 교체하지 않는다.
- 일반 로그를 먼저 복원하고 그룹의 회원 ID를 치환한다. 누락된 회원은 제외하고 빈 그룹은 건너뛴다. API 동기화도 일반 로그가 먼저다. 계정이 바뀌면 미리보기의 확인 작업은 거절하고 파일 재선택을 요청한다.
- 포함 사진은 브라우저에서 WebP/최대 1080px/기존 압축 파이프라인으로 처리한다. 손상/누락 사진 때문에 유효한 텍스트를 버리지 않는다. 가능한 원본 URL은 유지하며 복원 전 누락 수를 표시한다. 외부 URL만 있는 JSON은 해당 URL에 계속 의존한다.
- 선택 파일 250MiB, JSON 64MiB, 항목/ZIP 엔트리 10,000개, 개별 사진 30MiB, 추출 사진 합계 250MiB, 준비된 이미지 문자열 합계 100MiB를 제한한다. 압축 해제 전 엔트리 크기도 확인한다. 큰 백업은 오류로 중단하며 기존 로그를 유지한다.

## 검증

- `npm run build`, `npm run typecheck`.
- `test:context-restore`: 실제 날짜/불변 생성 시각, 잘못된 날짜, 공유용 복사본, ZIP/JSON ID·중복·그룹·손상 사진, 계정 변경·로컬 저장 실패·오프라인/재연결 처리.
- `test:context-browser`: Chrome와 Playwright WebKit. 검색·분류·카드 보기·정렬·스크롤 복귀, 320–1280px 공유 모달, 공개 범위 PNG 생성·지도 텍스트 제외·원본 유지, 실제 날짜 편집, ZIP 미리보기 전 쓰기 없음, 실제 WebP 압축·그룹 연결·반복 복원.
- `test:repository`: API 생성/내용 수정/디스크 재읽기에서 실제 날짜 보존을 추가했다. 기존 소유권·초안·그룹·프리셋·사진 보정 검사를 통과했다.
- `test:stability`는 Supabase의 동시 복원 insert 충돌도 검사한다. Chrome/WebKit `test:oct20-browser`, Chrome `test:calendar` 회귀 검사 통과. 기존 공유 검사들은 새 공개 범위 확인 단계를 거치도록 갱신했다.
- 모든 쓰기 검사는 격리된 저장소 또는 API fixture에서 실행했다. 운영 사용자 데이터나 유료 공급자 호출은 사용하지 않았다. WebKit 검사는 실제 iPhone/카카오톡 네이티브 공유창의 실기기 검사와 구분한다.
