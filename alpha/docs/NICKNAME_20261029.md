# Nickname onboarding and card metadata

- Real accounts without `preferences.nicknameConfigured` choose a nickname before entering the app. Existing alpha accounts see the step once too. Demo mode skips it.
- The existing `l2u_apply` transaction writes the profile and preference marker together. UI proceeds after acknowledgement; failed saves retain the input. No schema/Auth changes.
- Settings → profile → nickname change reuses the same validated form. Names are trimmed, NFC normalized, 1–30 codepoints, no control characters. Names need not be unique.
- Pending log changes remain recoverable before onboarding. Profile saves invalidate older refreshes and block concurrent commits.
- Card photo category and rating chips grow slightly; card dimensions and photo bounds stay unchanged.
- Group capacity fix in 8835b50 is included: input can be cleared; submit validates integer 1–20.

Validation: TypeScript, production build, nickname transaction/validation tests, disposable real account first save/edit/relogin (deleted after verification), mobile browser settings form and empty-value feedback. Physical iPhone PWA verification remains with alpha testers.
