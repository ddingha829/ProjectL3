# 모임 로그·근처 장소 알림

## 동작

- 설정에 `모임 새 로그`와 `근처에 남긴 기록` 스위치 추가. 기본값은 둘 다 꺼짐. 실제 계정과 기기의 명시적 알림 허용 후 사용한다.
- iPhone/iPad 홈 화면 웹앱에서 실제 계정으로 로그인하면 짧은 알림 안내를 한 번 표시한다. 기존 사용 안내·다른 모달이 끝난 뒤 열리며, `알림 설정하기`로 설정의 알림 항목에 이동한다. `나중에`와 닫기도 지원하며 계정별·기기별로 기억한다. 브라우저/예시 계정/이미 연결된 기기/권한 차단 상태에는 반복 권유하지 않는다. 안내 자체는 OS 알림이나 GPS 권한을 요청하지 않는다.
- 새 로그는 모임 공유 시 DB에서 발송 대상을 정한다. 개인 로그, 본인 기록, 비활성/탈퇴한 모임원은 제외한다. 한 기록을 여러 모임에 공유해도 기기당 한 번만 발송하며 수정만으로 다시 알리지 않는다.
- 근처 알림은 전경에서 현재 GPS와 접근 가능한 다른 사람의 기록을 기기 안에서 비교한다. 약 100m, 위치 정확도 80m 이하의 최신 위치만 사용한다. GPS 좌표는 알림 서버에 전송하지 않는다.
- 근처 알림은 계정 기준 6시간 간격이며 같은 장소는 다시 알리지 않는다. 장소 ID(또는 정규화한 좌표·장소명)로 구분하므로 새 로그 ID나 여러 모임으로 반복해 알리지 않는다. 두 기기가 동시에 접근해도 서버의 예약 잠금으로 한 번만 처리한다.
- OS 알림 표시 실패 시 예약을 해제한다. 표시 후 전송 확인이 끊긴 경우 기기 기록으로 반복 표시를 방지한다. 분산 네트워크에서 OS 실제 표시와 서버 확인을 단일 트랜잭션으로 보장할 수는 없다.
- 근처 알림 클릭은 해당 모임의 지도·장소로 이동한다. 새 로그 알림은 카드 상세로 이동한다. 실제 열기 시 현재 계정의 접근 권한을 확인한다.

## 웹앱 제약

새 로그 Web Push는 앱을 닫아도 지원된다. iPhone/iPad는 iOS/iPadOS 16.4 이상에서 홈 화면에 설치한 웹앱과 사용자의 직접적인 권한 요청이 필요하다. OS의 집중 모드·알림 설정·네트워크 상태에 따라 실제 표시가 달라질 수 있다.

웹 Geolocation은 `Window`에 노출되고 위치 요청은 문서의 표시 상태에 제약을 받는다. 웹앱을 닫고 이동하는 동안의 지속적인 지오펜스 감지는 지원하지 않는다. 탭이 숨겨지면 위치 감시를 해제하고, 6시간 대기 중에도 GPS를 계속 켜두지 않는다.

## 서버 구성

- 마이그레이션 7: private 알림 설정·기기 구독·장소 수신 이력·발송 큐·런타임 설정. 사용자에게 다른 계정의 구독 주소/키를 노출하지 않는다.
- `l2u_shares` INSERT 트리거가 큐를 만들고 `pg_net`으로 서버를 깨운다. 발송 실패가 로그 등록을 되돌리지 않게 분리한다.
- 서비스 키만 큐를 가져갈 수 있으며 재시도 시에도 알림 설정·현재 모임 권한을 확인한다. 만료/해지된 구독은 정리하고 최대 3회 시도한다. 미전송 큐는 5분마다 재확인한다.
- 알림 endpoint는 Apple/FCM/Mozilla/Windows의 HTTPS 서비스만 허용한다. 임의 URL·로컬 네트워크 접근은 차단한다.
- 로그아웃 때 기기 구독을 해제하고 서비스워커의 계정 정보를 지운다. 계정 전환 뒤 도착한 옛 알림은 표시하거나 열지 않는다.
- private VAPID 키와 서버 호출 비밀값은 환경 변수로만 관리한다. 공개되는 것은 VAPID 공개 키뿐이다.

## 적용 순서

1. SQL 마이그레이션 1~7 적용.
2. `supabase/notifications-runtime.sql`로 pg_net/pg_cron 연결. 빈 큐는 외부 HTTP 요청을 하지 않는다.
3. `node scripts/configure-notifications.mjs --prepare-local` — 키가 없을 때만 생성하며 값은 출력하지 않는다.
4. `--configure-server`로 DB의 비공개 worker 호출 설정 저장.
5. `VERCEL_CLI_JS`를 지정하고 `--configure-vercel`로 Preview/Production 변수 저장 후 배포.
6. 실제 설치한 휴대폰 두 대에서 가입·같은 모임 참여·알림 허용 후 새 공유 로그와 근처 알림을 확인.

초기화 전 백업과 삭제 승인은 별도 작업이다. 이 기능 자체는 기존 데이터를 삭제하지 않는다. 설치가 끝나지 않은 서버에서는 스위치를 활성화하지 않고 준비 상태를 안내한다.

## 검증

- `npm run test:notifications`: 거리/간격/안전한 링크·구독 주소, 서비스워커 계정 격리, 권한 요청·거절·계정 전환·백그라운드 전환, SQL 권한/중복/쿨다운/모임 해제 검증.
- `npm run test:db`: 새 마이그레이션을 함께 설치한 기존 49개 DB 동작 회귀 검사.
- 모바일 390×844 설정 화면: 가로 넘침 없음, 52×44 스위치 터치 영역, 예시 계정에서는 실제 권한 요청·발송 없음.
- 설치형 iOS 알림 안내: 표시 조건·기존 가이드/모달과의 순서·계정별 다시 보지 않기 등 18개 검사 통과. 390×844 UI에서 설정 이동·나중에 닫기·가로 넘침 없음 확인. 안내는 자동 권한 요청을 하지 않는다.
- 실제 iPhone/Android의 시스템 알림 수신과 백그라운드 전달은 휴대폰 설치 앱에서 최종 확인해야 한다.

## 라이브 활성화 완료

2026-10-28 마이그레이션 7, pg_net, pg_cron의 5분 재시도 작업, 비공개 worker 호출 설정을 실제 서버에 설치했다. VAPID/발송 비밀값은 Preview·Production 환경 변수에 적용했으며, Production 소스 `577388b`로 배포했다.

실제 HTTP 검사 17개 통과: 신규 계정 비밀번호 로그인, 기본 꺼짐, 알림 서버 준비 상태, 비밀키 비노출, 미인증·외부 Origin·비공개 네트워크 구독 차단, 근처 알림 예약/지도 링크/수신 확인/같은 장소 중복 방지/6시간 간격/해제 저장. 알림 표시 자체는 모의 수신 확인으로 검증했으며 실제 휴대폰 OS 수신을 대신하지 않는다. 검증용 계정과 자료는 삭제했다.
