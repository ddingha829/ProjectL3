# 가입 버튼 터치와 제출 상태

## 확인한 사실

- 사용자: iPhone 설치 앱에서 처음 2~3번 눌렀을 때 진행 표시나 오류 없이 무반응, 이후 가입 성공.
- 기존 공용 Tween 버튼은 focus/click 중 state를 갱신해 글자와 화살표의 keyed DOM을 교체했다. hover에서도 글자와 화살표가 이동했다. 모바일의 hover/focus/activation 순서에서 불필요한 변화를 만들었다.
- 데스크톱 브라우저의 단독 폼에서는 기존 버튼도 첫 제출에 성공했다. 사용자 실기기의 누락 이벤트를 직접 재현한 것은 아니므로 WebKit 원인을 확정하지 않는다.
- 현재 라이브 백엔드에 생성한 일회용 QA 계정은 signUp **한 번**으로 세션을 반환했다. 빈 snapshot, 같은 자격 증명의 로그인도 성공했다. 전체 검사는 412ms였으며 테스트 계정만 식별·검증 후 제거했다. 실제 사용자 계정·인증 설정은 변경하지 않았다.

## 수정

- 버튼의 내부 DOM을 유지하고, 움직이는 장식은 pointer-events:none으로 버튼에 터치를 모은다. focus/hover에서 자식 교체·이동을 하지 않는다.
- submit 버튼은 네이티브 form 제출을 그대로 사용한다. 다른 버튼은 고정된 자식에 클릭 후 Web Animations를 적용하며 reduced-motion을 존중한다.
- 가입·로그인·복구 폼에 즉시 동작하는 ref 잠금과 진행 상태를 표시한다. 성공 후 화면 전환까지 잠금을 유지해 재가입 요청을 막는다.
- FormData로 실제 제출 값을 읽어 비밀번호 관리자 자동완성과 React state 간 시간차에 대비한다.
- 실패 시 입력을 유지하고 오류를 표시하며 다시 제출할 수 있다. 8초 이상 대기 시 지연 안내를 표시한다. 계정 생성 요청을 자동 재전송하지 않는다.

## 검증

- `node scripts/serve-auth-ui-qa.mjs`: 실제 PreviewLogin과 공용 버튼을 로컬 mock 인증으로 렌더링한다. 실제 가입/메일/API 호출이 없는 수동 브라우저 회귀 도구다.
- 브라우저: 첫 클릭 → 요청 1개/진행 표시, 화살표 영역 클릭 → 요청 1개, Enter 제출, 실패 후 입력 유지와 재시도, 완료 뒤 연속 클릭에도 요청 수 유지 확인.
- 모바일 393×793에서 장식의 pointer-events:none, 진행/완료 표시 확인. 실제 iPhone 설치 앱 재확인은 사용자가 수행해야 한다.
- 인증 오류 메시지 회귀 10개, TypeScript, production build 확인.
