# 기존 Supabase 재사용 계획

사용자 결정: 기존 프로젝트를 초기화해 통합판 전용으로 재사용하며, 새 계정·빈 데이터로 시작한다. 옛 개인용 계정/로그와 Ticgle 자료는 이전하지 않는다. 요금제·프로젝트·기존 API 키는 유지한다.

## 준비 완료

최신 백업은 Git 밖의 제한된 로컬 폴더에 저장했다. 상세 경로는 작업 기기의 ignored `.test-data/reset-backup-path.txt`에 있다. 이전 백업도 보존한다.

- 6개 스키마, 79개 테이블의 3,852행과 구조/함수/RLS/트리거/권한 등 27개 카탈로그.
- 인증 계정 24개와 비밀번호 해시 포함, 기존 개인용 프로필 166개·로그 29개, Ticgle 게시글 33개 및 연결 데이터 전체.
- 사진·파일 502개, 163,854,125바이트. 파일별 SHA-256 검사 및 압축본 생성 완료.
- 격리 PostgreSQL에 앱·Auth·Storage·private 68개 테이블, 3,761행 복원 후 79개 검사 통과.
- 복원한 DB에서 초기화/재구성 9개 검사 통과. 통합판 테이블 12개와 마이그레이션 6개만 남고, 새 계정은 빈 기록으로 시작한다.

pg_dump가 아닌 카탈로그 기반 논리 백업이다. managed realtime/vault 원본은 저장했지만 격리 복원 대상에서는 제외했다. 플랫폼 키·실행 중인 Auth/OAuth·SMTP 비밀값·Storage HTTP 서비스 자체는 로컬에서 재현하지 않았다. 이 설정들은 프로젝트 재사용 과정에서 보존한다.

## 실제 적용 순서

1. **최종 삭제 확인을 받은 뒤** 잠시 가입을 중단하고, 읽기 전용 데이터 지문을 백업과 대조한다. 데이터가 바뀌었으면 변경분 백업 전에는 진행하지 않는다.
2. Storage API로 백업한 정확한 502개 경로를 삭제하고 비어 있는 버킷을 삭제한다. SQL로 object 행만 지우면 실제 파일이 남으므로 금지한다.
3. 검증한 SQL 트랜잭션으로 옛 가입 트리거·앱 테이블/함수·Storage 정책을 정리한다. 인증 계정과 연결 세션을 제거하고 알림 기능을 포함한 통합판 마이그레이션 7개를 설치한다. 관리 스키마/확장과 자동 RLS 보안 도우미는 유지한다.
4. 인증 기본 URL과 복구 URL을 현재 앱으로 정리하고, 이메일 즉시 가입을 유지한다.
5. `L2_BACKEND_GENERATION`에 새 식별자를 설정한 배포를 공개한다. 옛 로그인 정보는 재사용하지 않는다. 기기의 미전송 변경 원본을 자동 삭제하지 않는다.
6. 새 계정 가입/로그인, 개인 기록, 공유 모임·초대 코드, 사진 및 권한을 다시 검증한다.

## 2026-10-28 적용 완료

사용자의 `백업 보존 후 초기화 진행` 승인과 Supabase 재접속 후 실행했다. 원본 압축 백업을 보존했으며, 실행 직전 UTC 기준 읽기 전용 재수집으로 삭제 대상 30개 테이블의 데이터가 원본 백업과 일치함을 확인했다. 추가 운영 캐시 5행은 별도 보관했다.

- 백업한 정확한 Storage 파일 502개와 비어 있는 기존 버킷 3개 삭제 완료.
- 초기화 트랜잭션 커밋 후 계정·로그·모임·사진 모두 0개 확인. 기존 가입 트리거 제거.
- 통합판 마이그레이션 1~7 설치. public 12개와 private 9개 테이블 모두 RLS 활성화.
- 가입 재개, 이메일 인증 없이 즉시 가입 유지. Google·Kakao·Facebook 로그인은 비활성화.
- Site URL을 현재 Vercel 앱으로 변경하고 복구 허용 주소는 현재 앱 `/auth/reset`만 유지. SMTP 연결·발신 주소·비밀값은 유지하고 표시 이름만 `로그`로 변경.
- `L2_BACKEND_GENERATION=fresh-20261028`으로 옛 로그인 namespace를 분리. 로컬 미전송 원본은 삭제하지 않음.
- 신규 검증 계정 2개로 가입·로그인·6자리 초대·모임 공유·원본 수정 반영·강퇴 후 사진 접근 차단 등 19개 검사 통과. 알림 라이브 HTTP 검사 17개 추가 통과. 생성한 검증 계정·로그·모임·사진은 모두 정리.
- 알림 포함 소스 `577388b`를 Production `dpl_J1ZYP6V67iWUTqpaQ4QDEGQMHmmE`로 배포. 기존 주소 `https://project-l3-nine.vercel.app/` 유지.

사용자도 같은 이메일로 **새로 가입**해야 한다. 배포 롤백만으로 삭제된 DB가 복구되지는 않는다. 복구가 필요하면 별도로 보존한 논리 백업과 파일을 복원해야 한다.
