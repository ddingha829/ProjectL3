# 본문 전체 스와이프

기존의 지도·타일·일반 버튼 영역 차단 때문에 메뉴를 넘길 수 있는 표면이 일관되지 않았다. 화면 본문을 직접 좌우로 밀어 하단 메뉴 순서대로 이동하도록 수정했다.

- 피드 카드/리스트, 지도, 화면 안의 장소 목록, 일반 타일 보드, 스튜디오 카드 위에서 시작할 수 있다. 화면이 손가락 이동을 따라오고, 거리가 부족하거나 마지막 메뉴 바깥으로 밀면 제자리로 돌아온다.
- 모바일·마우스 입력을 동일한 Pointer Events의 캡처 단계에서 처리한다. 모바일의 Touch Events와 마우스 구현이 따로 달라지지 않게 한다. 세로 스크롤은 초기에 양보하고, 멀티터치/브라우저 취소/포커스 이탈은 진행 중인 이동을 취소한다.
- 지도는 기본 한 손가락 좌우로 앱 메뉴를 넘긴다. 두 손가락 이동/확대는 Leaflet이 처리한다. `지도 이동 모드`를 켜면 한 손가락 자유 드래그로 지도를 움직일 수 있고, 완료 버튼으로 메뉴 스와이프 상태로 복귀한다. 장소 선택기와 다른 간략 지도에는 이 규칙을 적용하지 않는다.
- 타일 팔레트는 가로 목록/위로 끌어 배치하기를 유지한다. 위치 편집 모드에서는 타일 이동이 우선한다. 일반 보드의 좌우 스와이프는 앱 메뉴를 넘기며, 여러 판은 기존 이전/다음 버튼으로 고른다.
- 텍스트 입력, 검색/필터 도구, 가로 목록, 지도 이동 모드, 타일 편집, 열린 대화상자는 자체 동작을 유지한다. 화면 가장자리 24px는 OS 뒤로가기 제스처에 양보한다.
- 트레이 같은 고정 요소의 기준 좌표가 흔들리지 않도록 본문 이동 표면만 변환한다. 프레임마다 React 상태를 갱신하지 않는다. 모션 감소 설정에서는 자동 페이지 진입/복귀 애니메이션을 생략한다.

## 검증

- 방향/거리/축 잠금/경계 저항 검사 23개, TypeScript, 프로덕션 빌드.
- 브라우저 390×844에서 리모콘을 사용하지 않고 피드 카드 → 지도 본문 → 타일 보드 → 스튜디오 카드와 역방향 전환 확인.
- 피드 리스트 버튼/지도 아래 로그 항목에서 스와이프해도 상세를 잘못 열지 않는지 확인.
- 지도 이동 모드에서 드래그 시 지도 좌표 화면만 움직이고 메뉴가 유지되는지 확인.
- 팔레트에서 빈 칸 배치 및 편집 모드 타일 드래그 시 메뉴가 유지되는지 확인.
- 실제 기기의 두 손가락 입력은 테스트 브라우저의 입력 도구로 재현하지 못해 추가 확인이 필요하다.
