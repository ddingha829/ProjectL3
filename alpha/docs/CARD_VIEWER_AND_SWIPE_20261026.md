# 화면 스와이프와 카드 상세 패널

- 하단 메뉴 순서(피드 → 지도 → 타일 → 스튜디오)에 따라 좌우 스와이프로 이동한다. 마지막 메뉴에서는 순환하지 않는다. 피드에서 오른쪽으로 미는 기존 로그 추가 진입은 유지한다.
- 화면 가장자리 24px는 OS 제스처에 양보한다. 세로 스크롤, 폼 입력, 가로 목록, 열린 대화상자에서는 페이지 전환을 시작하지 않는다.
- 지도 캔버스의 드래그/확대와 타일 보드의 배치/페이지 넘김은 해당 컴포넌트가 처리한다. 이 화면에서 앱 메뉴를 넘길 때는 상단 여백이나 하단 메뉴 영역을 민다.
- 카드 상세의 아래 패널은 작성자·날짜·댓글 수와 손잡이를 처음부터 노출한다. 헤더를 누르거나 위로 끌면 펼쳐지고, 다시 누르거나 아래로 끌면 접힌다. 화살표 버튼은 제거했다.
- 펼친 패널은 모바일 높이의 약 27%(214~238px)를 사용한다. 공감·담아두기·공유는 아이콘으로 표시하며 접근성 이름과 상태를 유지한다. 댓글 목록은 패널 안에서 스크롤하고 입력란은 유지한다.
- 내용 수정, 카드 꾸미기, 프리셋, 공유 대상 등은 더보기로 옮겼다. 카드/플립/이미지 내보내기 루트는 패널을 여닫아도 유지한다.
- 가로 780px 이상에서는 카드 왼쪽·패널 오른쪽 배치를 유지한다. 모션 감소 설정에서는 페이지 및 패널 전환 애니메이션을 생략한다.

## 검증

- `node scripts/test-page-swipe.mjs`: 방향·거리·세로/대각 제스처·탭 경계 16개 검증.
- TypeScript 검사 및 프로덕션 빌드.
- 브라우저 390×844 / 1280×800에서 카드 크기·패널·가로 넘침 점검.
- 실제 포인터 드래그로 메뉴 양방향 전환, 지도 이동 시 메뉴 유지, 패널 끌어 열기 확인.
- 예시 데이터로 공감·담아두기·댓글 작성, 카드 플립, 공유 형식 선택창, 더보기와 카드 꾸미기 확인.
- 물리 휴대폰의 터치 입력은 사용자 기기에서 추가 확인할 수 있다.

이 변경은 통합판 Preview 브랜치에만 배포한다. 개인용 Production은 교체하지 않는다.
