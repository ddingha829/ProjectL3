# 타일 배치 상태에 따른 크기 변화 수정

## 원인과 변경

미배치 목록의 포스터 높이와 빈 목록 안내의 높이가 달랐고, `data-empty=true`에서 팔레트 자체를 더 낮은 flex 레이아웃으로 바꾸고 있었다. 남은 공간으로 폭을 정하는 보드가 팔레트 상태에 따라 다시 계산되는 원인이었다.

- 캡처의 배치된 상태를 기준으로 팔레트 행을 기본 110px로 고정했다. 짧은 화면은 90px, 360px 이하의 짧은 화면은 78px로 반응형 조정하되 후보/빈 목록/이동 모드 간에는 같게 유지한다.
- 빈 팔레트의 별도 레이아웃을 제거하고 목록·안내·회수 버튼이 같은 공간을 사용한다.
- 기존 4×4 그리드와 포스터 비율, 기본 보드 폭 계산은 유지한다.
- 바깥 회색 도트 배경과 안쪽 베이지 프레임을 제거했다. 빈 칸은 옅은 중립 배경·가는 점선·작은 +로, 배치된 포스터는 흰 테두리·작은 그림자로 구분한다.
- 페이지 이동/위치 이동은 작은 알약 조작부로 유지하고, 팔레트는 얇은 유리 표면으로 정리했다. 피드·지도·스튜디오 및 공통 리모콘 CSS는 변경하지 않았다.

## 검증

실제 예시 계정 UI에서 TMDB 검색으로 작품을 등록하고, 타일 선택 → 빈 칸 배치 → 위치 이동 → 트레이 회수 → 드래그 배치 → 이동 완료를 확인했다. 계정·실제 로그 서버 데이터는 변경하지 않았다.

- 393×793: 배치 전/후 보드 318.17×461.19px, 첫 칸 69.53×91.78px, 팔레트 357×110px, 리모콘 bottom 779.08px로 좌표와 크기 모두 동일.
- 320×568: 후보가 있는 이동 모드와 배치 완료 모드 모두 보드 192.42×299.50px, 첫 칸 44.59×58.86px, 팔레트 296×78px로 동일. 조작부가 보드 폭 안에 들어오며 가로 넘침 없음.
- 탭 배치, 트레이로 회수, 위로 드래그해 6번 칸에 배치, 라이트/다크 확인.
- 비교 결과: `.test-data/mosaic-layout-comparison.json`. 로컬 화면: `.test-data/mosaic-open-grid-light.png`.

실제 iPhone 설치 앱 결과는 별도 확인 대상이며, 브라우저 검증을 실기기 검증으로 간주하지 않는다.
